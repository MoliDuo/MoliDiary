# 架构

Moli Diary 是单用户的个人日记：写下的内容在数据库里只存密文，AI 在后台给每篇生成标题、摘要和标签。一页纸说清模块、数据流和几个关键决定；细节看代码和 [内容加密](encryption.md)、[部署](deploy.md)。

## 模块

| 位置                          | 做什么                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `src/app/`                    | Next.js App Router：页面、`/api/*` 接口、`/healthz`、manifest 和图标                                    |
| `src/proxy.ts`                | 每个请求先经过：网关没有确认是管理员就返回 403，没有解锁会话就跳到解锁页，并给响应加 nonce CSP 等安全头 |
| `src/components/`             | 界面组件；`ui/` 是 shadcn/ui 风格的基础件                                                               |
| `src/lib/actions/`            | Server Actions：新建、编辑、删除、整理、设置、主密码和 API 令牌                                         |
| `src/lib/db/`                 | node-postgres 连接池、Drizzle 结构（`schema.ts`）、条目和标签的读写                                     |
| `src/lib/crypto/`             | 字段加密（AES-256-GCM）、密钥槽（主密码、会话、API 令牌各自包裹同一把数据密钥）                         |
| `src/lib/auth/`               | 网关身份（`Remote-User`、`Remote-Groups`）、主密码解锁、会话、解锁限流、API 令牌                        |
| `src/lib/ai/`                 | 进程内常驻 AI 队列：把正文发给 OpenAI 兼容接口，写回标题、摘要和标签                                    |
| `src/lib/background-tasks.ts` | 启动时开 AI 队列和每小时一次的清理（过期会话、解锁记录、回收站），停止时等任务收尾                      |
| `scripts/`、`drizzle/`        | 迁移和密钥维护命令（打包进镜像的 `tools/`）、Drizzle 生成的迁移文件                                     |
| `deploy/`                     | 服务器上应用目录的模板：compose、备份脚本、迁移命令、部署前备份                                         |

## 数据流

1. 浏览器或 API 客户端带着会话 cookie 或 API 令牌发来请求；`proxy.ts` 放行或拒绝。
2. 令牌或会话把数据密钥解出来，只放在这次请求的内存里。
3. 写日记：正文用数据密钥加密后入库，条目标记为待整理，交给 AI 队列。
4. AI 队列取出条目，带着数据密钥解密正文、发给 AI、把结果加密写回；失败自动重试，进程重启时没做完的标为失败，界面里可重新整理。
5. 读日记：从库里取密文，当场解密；搜索也是服务端解密后匹配，因为库里没有明文可查。
6. `/healthz` 查一次数据库，返回 `{"ok":true,"version":"<提交哈希>"}`，部署脚本靠它确认上线的是刚构建的那个提交。

## 关键决定

| 决定                                     | 原因                                                                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 内容只存密文，数据密钥由主密码包裹       | 拿到数据库、备份或服务器环境变量的人都看不到日记；代价是忘记主密码无法恢复，搜索只能在服务端做                          |
| 登录交给 Authelia 网关，主密码只负责解锁 | 身份和密钥分开：Authelia 管“你是不是管理员”（规范 008 的 P2），主密码管“能不能解开数据”，服务器仍不保存任何能解密的秘密 |
| Postgres 而不是 SQLite                   | 数据从 Neon 带过来，查询和迁移都是按 Postgres 写的；改成 SQLite 要重写全部查询并迁移数据                                |
| AI 队列放在进程内，所以只能运行一个实例  | 队列要拿着数据密钥，放进进程内存就不用把密钥交给任何外部队列；单用户的规模一个进程足够                                  |
| 迁移只加不删                             | 部署切换和回滚时新旧版本同时存在，旧代码必须还能用新结构                                                                |
| 镜像里自带迁移和密钥维护命令（`tools/`） | 部署脚本用同一个镜像执行迁移，迁移和代码版本一一对应                                                                    |
| 网页框架用 Next.js                       | 存量应用沿用，规范 010 允许；服务端渲染配合每次请求的 nonce CSP                                                         |
